## 2. 转换工具

- **输入：** `MANIFEST.tsv` 加 `repos/` 卷，只读，不改原始数据。
- **输出：** `<out>/<user>/<repo>_HEAD.tar.gz`，包内是 `<repo>-HEAD/...`，跟 `github_downloads` 的布局一样。
- **三种格式：**
  - `.bundle`：在临时裸仓库里执行 `git bundle unbundle`，再用 `git archive` 导出 `swh_rev` 这个提交。
  - `.git.tar`：先解开裸仓库，再用 `git archive` 导出。
  - `.dir.tar`：改成 `<repo>-HEAD/` 前缀，重新打包成 gzip。
- **提交缺失时：** 依次回退到 HEAD、main、master，最后是第一个分支。
- **并行：** 用 `--workers` 指定并发数。
- **断点续跑：** 已有的成品文件直接跳过。
- **原子写入：** 先写 `.tmp`，完成后再改名。
- **日志：** 每个仓库一行，记在 `convert_log.tsv`，包括状态、实际用的提交、输入和输出大小、耗时、错误信息。
- **临时文件：** 放在 `/tmp`，处理完就删。
- **其他参数：**
  - `--only-new DIR`：跳过 `github_downloads` 已有的仓库。
  - `--ids-file`：只转指定的仓库。
  - `--sample/--seed`：随机抽样。
  - `--verify-sha256`：校验输入文件的 sha256。
- 同时生成 `repo_metadata.tsv`，可以直接给 `dedup.repo_metadata_path` 用。里面只有 stars，`MANIFEST.tsv` 没有 forks、创建时间和许可证。
- 单元测试 `tests/test_bundle_to_tar.py` 覆盖三种格式，还测了按清单提交导出、HEAD 回退、断点续跑、临时文件清理和元数据，已通过。
- 代码在本地提交 `dea679d`（工具和测试），试跑配置在 `configs/pilot-repos-20261117.yaml`。没有推送。

## 6. 发现的问题

1. **写权限：** `/mnt/data4/cleaning_data/` 顶层属于 `tpc`，我的账号写不进去，所以转换结果放在了 `dataflow_runs/repos_tar_pilot_20261117/`。全量建议也放在 `dataflow_runs/` 下面，或者让 `tpc` 新建一个目录给写权限。
2. **未识别语言占 6.2%：** 主要是 `.seml`（2,234 个，全在 `semarchy/sdp-accelerators`）、`.sub`、`.vcd`、`.fxc` 这类小众格式，enry 不认识，目前照样保留。要不要过滤，需要单独定一条规则。
3. **解码失败偏多：** 2,539 个，旧批次试跑只有 70 个。还没细查是哪些仓库，猜测是少数仓库里有大量非 UTF-8 的文本，全量前可以抽查一下。
4. **元数据只有 stars：** 跨批次去重选代表时，`github_downloads` 的仓库只有跟清单重合的那部分有 stars。
5. **`.dir.tar` 只有 1 个**，内容是 swh 的目录快照，不是完整的 git 历史，跟旧包有差异，影响可以忽略。
6. **字节预算的上限：** 2GB 这个上限是按一个批次定的，两个批次合并后，JSON 这类格式的上限要不要跟着放大，需要你定。

## 7. 全量建议

1. **只转新仓库：** 用 `--only-new github_downloads`，49,025 个仓库，32 并发约 3.4 小时，产出约 206 GB。
   - 重合的 4,533 个仓库里约 88% 跟旧包完全相同，不用重复转。
   - 如果想用更新的快照替换旧包，可以以后单独转。
2. **跨批次去重：** 去重只在一次运行内部做，所以需要新建一个合并输入目录，同时放 `github_downloads` 和新转换的结果（用符号链接，不复制数据），一次跑完，输出到新目录，比如 `full-combined-2026111x`。
   - 这样新旧两批会一起做完全重复和近重复去重，代表按 stars 选。
   - 不覆盖 `full-rules-20261111`。
3. **预计耗时：** `full-rules-20261111` 处理 174.7 GB 的 tar.gz 用了 4 小时 15 分。合并后是 381 GB，线性推算约 9.5 小时；近重复候选对会增多，按 **10 到 12 小时** 准备。
   - 中间文件预计 250 到 300 GB，NFS 空间够。
4. **顺序：** 先转换（3.4 小时），再跑合并清洗（10 到 12 小时），总计大约 14 到 16 小时。
