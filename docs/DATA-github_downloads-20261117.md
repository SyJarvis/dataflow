## 4. 清洗规则（`full-rules-20261111`）

镜像是 `dataflow:rules-20261111`，配置文件是 `configs/full-rules-20261111.yaml`，代码提交是 `747bad0`。

1. **解包：** 丢掉单个超过 5MB 的文件，丢掉前 64KB 里有空字节的文件（按二进制处理），丢掉符号链接，丢掉文件数超过 100 万的仓库。
2. **语言识别：** 用 go-enry 识别语言，丢掉无法解码的文件。
3. **Notebook：** 先去掉输出和图片，再交给质量过滤。
4. **质量过滤：** 用 Unicode 规则算字母占比（中文也算字母），再检查行长、自动生成文件、编码数据块、HTML 可见文本比例、LFS 指针等。
5. **去重：**
   - 先按 sha1 做完全重复去重。
   - 再做近重复去重：MinHash 256 个排列、5-gram，跨仓库、跨语言，用真实 Jaccard 复核，达到 0.7 才合并。
   - 保留哪一份按 stars、forks、许可证、创建时间排序。
6. **配额：**
   - 超过 1.5 GiB 的仓库按 50% 降采样。
   - XML、HTML、JSON、JavaScript 每种格式最多留 2GB。
7. **不启用：** PII 过滤、许可证过滤、年份限制、密钥文件过滤、控制字符检查。

## 7. 去重情况

**完全重复，共 7.45 GB：**

- 跨仓库 5.62 GB，占 75%；同一仓库内 1.83 GB。
- 按语言看，最多的是 Gettext 翻译文件 2.73 GB，其次是 Markdown 0.86 GB、TypeScript 0.75 GB。
- 路径带 `node_modules`、`vendor` 的文件占 0.90 GB。
- 典型例子是课程作业 fork：`TTDN-16-05-N1`、`N8`、`N9`、`N10` 是同一份作业，每个仓库因完全重复丢掉约 0.62 GB。

**近重复，762,786 个文件：**

- 复核了 1,425 万对候选，其中有 49.6 万对估计值达到 0.7、真实 Jaccard 不到 0.7，没有合并。
- 近重复和降采样合计 6.99 GB。降采样只碰到一个仓库，大概率是 `worldwidelaw/legal-sources`，单独的字节数没有拆出来，估计是几百 MB。

**结论：** 去重加配额一共只占解压后总量的 6%，规则本身合理。数据量主要是因为原始数据里非文本内容占比太高才变小的。

## 8. 已知问题

- **超过 5MB 的大文本：** 一共 28.33 GB 被丢掉了，多数是 json、jsonl、csv 这类数据文件，也有一部分是大的 Markdown。如果需要更多数据，可以重新考虑这条上限。
- **JSON 配额：** 2GB 上限是照 Stack v3 的思路定的，调高或取消最多能多留 2.06 GB，只需要重跑配额这一步。
- **Smali：** 0.47 GB，是 Android 反编译出来的代码，还没过滤。
- **unknown：** 0.55 GB，是 go-enry 识别不出语言的文件。
- **活跃年份分布：** `activity_year_hist` 里有 2027 到 2039 这些未来年份，还有 1,750 个仓库是空值，说明压缩包里的文件修改时间不可靠。这个字段只作参考，不参与筛选。
