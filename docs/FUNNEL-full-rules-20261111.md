## 那大约 100GB 都是什么

先纠正口径。162.7 GiB 是 10,034 个压缩包的总大小（174,701,509,259 字节 = 174.70 GB），不是解压后的文本体积。742 个损坏包一共只有 10,388 字节，可忽略。9,292 个能打开的包解压后，常规文件合计 **289.31 GB**。最终留下 **34.64 GB**。

差额的大头不是去重，而是解包规则按你定的目标扔掉的非文本和大文件：

## 去重是否太狠

**结论：相对「那 100GB 去哪了」这个问题，去重并不狠。** 289.31 GB 里去重加预算只切掉 16.50 GB。代码语言在质量之后到最终，主要是去了副本，而不是被字节预算砍掉（预算只碰到了 JSON）。

### 精确去重（已测，规则合理）

- 丢掉 896,812 个文件、7.45 GB，全部是 SHA-1 完全相同的副本。
- 其中 **跨仓库 5.62 GB（75.4%）**，仓库内 1.83 GB（24.6%）。
- 最大一块是 Gettext 翻译文件 2.73 GB，其次是 Markdown 0.86 GB、TypeScript 0.75 GB、Python 0.58 GB、JavaScript 0.51 GB。
- 带 `node_modules` / `vendor` / `third_party` 等路径的占 0.90 GB。
- 最典型的是一组课程作业 fork：`bbikem/TTDN-16-05-N1`、`tranchienthinh-0000/TTDN-16-05-N10`、`phuonganh29-12/TTDN-16-05-N9`、`antruong2004/TTDN-16-05-N8` 各自因精确去重丢掉约 0.618 GB，内容是同一份作业的完整拷贝。这正是精确去重要做的事。

### 近重复（阈值 0.7，真实 Jaccard 复核，不算松）

- 丢掉 762,786 个文件。与大仓降采样合计 6.99 GB；降采样只有 35,110 个文件，近重复占这个合计的绝大部分（估计近重复约 6.6–6.9 GB，降采样大约几百 MB，降采样为估计）。
- LSH 候选约 1.54 亿对，复核 1,425 万对；**有 495,961 对估计值 ≥ 0.7、真实 Jaccard < 0.7，已被拒绝合并**。这次比只看 MinHash 估计更严，不是更松。
- report 里拒绝样本的真实 Jaccard 大约在 0.64–0.70，说明卡在阈值附近的对确实没有被合并。accepted 对的真实 Jaccard 没有存盘，这次没有再扫 58GB 中间文件去抽样 20 对，故不做虚构样本。
- 质量后未进入最终结果、且语言不是 JSON 的 unique sha1（近重复 + 降采样，不含 JSON 预算）共 650,072 个文件、约 4.81 GB。其中只有 49,461 个（0.42 GB）与另一个仓库最终保留文件有完全相同的路径，其余没有这条「同路径拷贝」证据。这不能证明误伤，只说明近重复并不都是简单的同路径 fork。
- 这部分里体积最大的语言是 Markdown 1.32 GB、Python 0.46 GB、TypeScript 0.44 GB。Markdown 偏高，符合大量 fork / 拷贝文档被合并的情况。
- 超过 1.5 GiB、被降采样的那一个仓库，最像 `worldwidelaw/legal-sources`（精确去重后仍有 2.42 GB unique 内容，其中 1.86 GB 未进入最终结果且几乎全是 JSON）。未完全证实，所以降采样字节仍与近重复合计。
