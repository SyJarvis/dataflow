### 3.5 关键性能测量（**这次调查最重要的产出**）

复刻 `EnryDetector._detect_via_cli` 的完整调用路径实测：

```
20 个文件耗时 0.78s → 单文件 39.2 ms
按 3,756,446 个文件外推 → 40.9 小时（单进程）
```

**根因**：`src/dataflow/languages.py` 的 `EnryDetector._detect_via_cli` 对**每个文件**执行一整套：
1. `tempfile.TemporaryDirectory(prefix="enry-")` 建临时目录
2. `os.makedirs` 重建目录层级
3. 写文件（`content[:64*1024]`）
4. `subprocess.run([enry, "-json", path])` **起一个 Go 进程**
5. `json.loads` 解析输出

375 万文件 = 375 万次进程创建 + 375 万次临时目录读写 + 375 万次 JSON 解析。这是当前方案不可直接用于全量的原因。

### 4.3 方案 B 的一个必须注意的陷阱

如果选 B（只重打标签），**不能只更新 `language` 字段就完事**。`quality.py` 有 **6 处依赖 `language`**：

| 位置 | 规则 | 影响 |
|---|---|---|
| `data_format_line_cap` | JSON/YAML/TOML/CSV/XML/INI/Properties 封顶 512 行 | 新识别为 JSON 的文件可能被丢弃 |
| `line_len_exempt` | Text/JSON/XML/HTML/Markdown/Roff/TeX 免行长限制 | 新识别为 Markdown 的文件可能从"丢弃"变成"保留" |
| `alpha_ratio` | Assembly 按字母数字统计，其他按字母 | 语言变化会改变通过率 |
| `html_min_visible_chars` / `html_min_visible_ratio` | HTML 可见文本 ≥100 字符且 ≥20% | 新识别为 HTML 的会重新判定 |
| `byte_budget` | XML/HTML/JSON/JavaScript 字节预算 | 语言变化影响预算归属 |

**所以方案 B 必须"重打标签 + 重跑 quality 过滤"两步一起做**，否则产出的文件集合与 `language` 字段不自洽。

## 七、踩过的坑（避免重复）

| 坑 | 现象 | 解法 |
|---|---|---|
| Go 校验数据库被墙 | `sum.golang.org` i/o timeout 导致 build 失败 | Dockerfile 加 `GOSUMDB=off` |
| NFS 跨机器 gid 不一致 | 108 是 1003，h100 是 1004，`chgrp` 只对一台有效 | 用 **other 位**（`a+rX` / `a+rwX`），与身份无关 |
| sudo 需要密码 | `sudo -n true` 失败 | 用 docker 组 + 未开 root_squash，容器内 root 直接改 |
| 用错比对基线 | 拿 pilot run（10 个仓库）的 inputs.json 对比全量，误报"10024 个新增" | 必须用 `full-20261026/manifest.json`（10034 条） |
| macOS tar 垃圾文件 | 解压出 60 个 `._*` 文件 | `find . -name "._*" -delete` |
| 只读挂载导致修复失败 | `touch -r` 报 `Read-only file system` | Docker `-v` 不要加 `:ro` 才能写元数据 |
| `cp -p` 保留时间戳失败 | 非属主不能设 mtime，报 `Operation not permitted` | 用 `docker run` 以 root 执行 `touch -r` |
| 大目录 `head -c1 "$P"/*` | 展开成 8532 个参数，测试逻辑失效 | 用 `find -perm -o+r` 或逐个文件测 |
| `ssh host 'sh -c "..."'` 引号嵌套 | `unexpected EOF` 语法错误 | 脚本写成文件后 `ssh host 'docker run -i ... sh -s' < script` |

## 八、一句话总结给接手者

> 108 上代码和镜像（`dataflow:latest`）都已就绪，enry 能跑通。**唯一卡点是不知道改 enry 后 `unknown` 能从 10.26% 降到多少，以及 `_detect_via_cli` 39.2 ms/文件太慢（全量要 40.9 小时单进程）**。建议先向用户确认输出目录和改码授权，然后花 10 分钟做 pilot 量化收益，再决定全量重跑还是重打标签。**不要直接开全量。**
